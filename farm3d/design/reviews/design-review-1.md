## 跨系统冲突清单（technical-director 视角）

1. **热路径零分配**：技能路径池每帧遍历，`Skill.fx` 必须预分配 + `count` 复用，不允许在逐帧循环里 `new`（现有 `C.hit` 是直线调用，别把每帧新建对象引入热路径）。
2. **位移 `dash` 与碰撞的先后顺序**：先计算新位置 → `Builds.pushOut` → `Nodes` 碰撞 → `Dungeon / World` 边界夹取。**这个顺序必须写死在 Story 验收里**，否则会出现「卡进墙里」或「被推出世界」。
3. **`level_mult` 与副本逐层难度的叠加**：副本 `lvMul`（`combat.js:142`）已经在涨血量，再叠加 `-20%` 等级压制，低等级玩家可能连第一层都打不动。建议处理：副本内把 `level_mult` 下限放宽到 `-0.1`，或让压制只对开放世界生效。**需要 playtest 数据才能定，本轮不下结论**。
4. **艺术资产与移动端预算的冲突**：bloom 与技能特效同时存在时，移动 GPU 的填充率是主要瓶颈。文档已要求移动端默认关闭 bloom，这条必须保留。

## 建议的落地顺序（producer 视角）

四个方向的依赖关系：**战斗技能 → 天赋数值 → 视觉/音频**（技能面板要挂天赋页，视觉要为技能提供动画与特效，音频要为技能提供两个音锚点）。因此：

```
S1 战斗技能骨架：冷却 / 资源 / 一个 melee 技能端到端跑通
S2 天赋最小闭环：战斗树 + 聚合 mods + 接入伤害公式
S3 剩余七个技能 + 五种释放路径补全
S4 视觉：程序化纹理 + 动画层
S5 音频：音乐层 + 音效字典（与 S3 的技能音锚点对接）
```
