# GDD：战斗技能系统

- **ID**：combat-skills
- **Status**：Approved（S1 已实现，见 `docs/architecture/adr-0001-combat-skills.md`；开放问题 1/2/3 已裁决）
- **依赖系统**：`combat.js`（怪物与伤害）、`player.js`（玩家动作与模型）、`rank.js`（`F.Skills` 八项技能等级）、`interact.js`（输入分发与键位）、`util.js`（键位映射 `F.bind`）
- **被谁依赖**：天赋数（`talents-and-numbers.md`）、副本结算（`dungeon.js`）、UI 技能面板（`ui.js panelSkill`）
- **优先级层**：Core
- **MVP**：Yes

## 1. 目的与玩家价值

**现状（已核实）**：`combat.js:297 playerAttack()` 是唯一的攻击手段——0.52s 冷却、锁定 3.4m 内最近目标、工具伤害表 + 装备攻击力、12% 暴击 ×1.8、`playAction('chop', 0.42)` 一个挥砍动作。**没有任何主动技能**：没有前摇、没有释放路径（弹道/位移/范围）、没有资源管理、没有技能与技能的组合。

本系统为战斗补上「决策层」：同一个怪，玩家可以重斩单点爆发、旋风斩清群、突进斩拉近拉开距离、飞刃在安全距离输出。目标是把「按住 F 贴脸磨」变成「读怪的行为 → 选技能 → 承担冷却与资源代价」。同时它给副本 33 层提供难度曲线所需的输出杠杆。

非目标：不加职业切换、不加转职、不做多人同步（游戏是单机本地存档）、不改普攻的手感基线（普攻保留，仍是无消耗输出）。

## 2. 核心机制

### 2.1 技能的三段式时间线

每个技能走同一套时间线，动作、路径、伤害都挂在上面（这是"释放动作 / 释放路径 / 伤害"三件事能被一起验收的前提）：

```
按键 → 施法前摇 windup → 结算帧 damageT → 收招 recover → 冷却 cd 开始
```

| 段 | 含义 | 期间玩家能不能移动 |
| --- | --- | --- |
| `windup` | 播放起手动作（如举刀、蓄力） | 可以移动，速度 ×0.35（沿用 `P.action` 现有减速） |
| `damageT` | **伤害在这一帧结算**，同时生成路径表现 | 不能（除位移类技能本身） |
| `recover` | 收招后摇 | 可以移动，速度 ×0.6 |
| `cd` | 从释放开始计时 | 完全自由 |

### 2.2 释放路径（Release Path）— 五种，覆盖全部技能

| 路径 | 结算形状 | 表现 | 用它的技能 |
| --- | --- | --- | --- |
| `melee` | 扇形：正前方 `range` 内、`angle` 张角 | 挥砍弧线残影 | 重斩、终结技 |
| `around` | 圆：以自身为心、`radius` 半径 | 旋转环 | 旋风斩 |
| `dash` | 线段：**玩家自身位移**，沿路径沿途每 0.06s 判定一次（去重集合） | 拖尾 + 位移插值 | 突进斩 |
| `projectile` | 飞行体：以 `speed` 沿朝向前进，每帧做球形扫掠命中判定，`life` 到期消失 | 实体 mesh + 命中爆点 | 飞刃 |
| `ground` | 延迟圆形：地面标记后 `delay` 秒结算 | 地面警示环由细到实 | 地刺、雷暴 |

工程约定：路径是**一个 `update(dt)` 驱动的实例**，统一进 `F.Skills.fx pool`（数组，每帧遍历），命中判定走 `C.nearestInRealm` 同款的距离筛选 + `AndAlso` 去重（避免打过地形的/已死的）。

### 2.4 资源

**这里有两个方案，需要你拍板（涉及存档 schema）**：

- **方案 A（不动 schema）**：技能消耗**体力 `P.energy`**（现成字段，已在 UI 显示、已有恢复/药水循环）。优点：零迁移风险，立刻能做；缺点：跳跃与奔跑也吃体力，四个系统抢同一份资源，战斗续航与探索续航互相挤压。
- **方案 B（schema 变更）**：新增法力 `P.mana / P.manaMax`，随战斗等级成长，脱离体力独立恢复。优点：资源分层清晰，天赋可以分别投资两条；缺点：要改 `Game.save/load` 与读档兼容，**属于必问类目**。

默认建议 **A 先做**：垂直切片阶段不该让迁移风险盖住玩法验证；如果 B 批准，A 的产物（CD / 路径 / 倍率）全部保留，只把 `cost.energy` 换成 `cost.mana`。

### 2.5 释放输入（也是待批点）

现状：`1~9` 固定给工具快捷栏（`ui.js:87`），`Q` 切种子、`X` 拆除、`R` 投球、`F/G` 双交互、`TAB` 地图，全部走 `F.bind` 可改表。**技能没有干净的默认按键**。三个候选：

- **候选 1**：技能槽 3 个，`Q` / `E` / `鼠标右键` 释放，`Shift+滚轮` 或技能面板切换装配的技能。（与现有 Q 切种子冲突，需要把切种子移到 Z 或 `Alt+Q`）
- **候选 2**：技能槽 6 个，用 `Alt+1~6` —— 不占现有单键，但手机上没法用。
- **候选 3**：保留 `1~9` 工具，新增 **`Ctrl+1~6`**。PC 顺手，移动端不适用。

三个候选都不完美，因为**这游戏还要支持 iOS/Android 触摸**——所以技能释放必须同时有屏幕按钮方案，见 §5。

## 3. 公式与数值

统一伤害公式放在 `talents-and-numbers.md` §3；本系统只定义技能对公式的贡献：

```
skill_damage = base_attack * skill_mult * (1 + talent_mult) * crit_mult * level_mult
```

| 常数 | 值 | 说明 |
| --- | --- | --- |
| `base_attack` | `tool_dmg + equip.atk` | 沿用 `combat.js:307-308` 现状取值 |
| `skill_mult` | 见 §2.3 表 | 每技能固定倍率 |
| `talent_mult` | 0 ~ +0.75 | 天赋系统注入（`talents-and-numbers.md`） |
| `crit_mult` | 1.8（暴击） / 1.0 | 暴击率 `0.12 + talent_crit`，上限 0.75 |
| `level_mult` | `1 + clamp((combatLv - mob.lv) * 0.01, -0.20, +0.30)` | 等级压制双向生效，防止跨级秒杀也防止高等级碾压无收益 |
| 最低伤害 | `max(1, round(...))` | 沿用现状下限，防止 0 伤害导致怪物永远打不死 |

资源消耗（方案 A）：

| 技能 | 体力消耗 | 备注 |
| --- | --- | --- |
| heavy / dash / quake / finisher | 8 / 10 / 14 / 18 | 大招更贵 |
| whirl / blade / chain | 12 / 3 / 10 | blade 便宜但低倍率，作为远程填充 |
| mend | 12 | 恢复类 |

释放**门槛**：`energy >= cost`，否则 `F.UI.toast('体力不足')` + `Audio2.bad()`（与跳跃静默失败的修复保持同一口径）。

## 4. 边界与异常用例

| 情况 | 行为 |
| --- | --- |
| 冷却中再次按键 | 不进入前摇，播 `bad` 轻提示，**不消耗资源**，不打断当前普攻 |
| 前摇期间受伤打断 | 草案：**不打断**（休闲向，保手感）。眩晕类怪物控制技能若将来加入，再定义打断规则 |
| 释放瞬间目标死亡/离场 | 路径照常飞完（`blade` 落空），范围技能对活着的单位结算；`melee` 无目标则视为空挥，浪费 CD |
| 位移撞到世界边界 | 突进被 `r <= 283` 边界夹住（沿用 `player.js:137`），沿途伤害结算到实际位移段 |
| 位移路径经过建筑/树 | 突进可穿（设计意图就是这样用来脱围），但终点位置必须过 `Builds.pushOut` 与 `Nodes` 碰撞，不能卡进墙体 |
| 弹道击中水体/地形 | 碰到地形高度以上即消失（`T.hAt` 判定），不穿墙 |
| 存档版本落后（无熟度/无技能字段） | 读档后缺字段补默认值，**不清零玩家进度**（具体默认值见目标任务 Story） |
| 同名技能重复装配 | 装配表去重，一个槽只能一个 id |
| 室内/副本边界 | 位移技能不得把玩家送出副本地牢外圈，`Dungeon.clampPlayer` 在结算后再夹一次 |
| 帧率过低（dt 异常大） | 所有路径计算走 `dt`，且单帧上限 `dt = min(dt, 1/20)`，防止大卡顿帧让弹道"跳穿"目标 |

## 5. 与其他系统的接口

| 对端 | 输入 | 输出 | 谁持有状态 |
| --- | --- | --- | --- |
| `combat.js` | 技能 id、释放者、目标集合 | 走 `C.hit(m, dmg, crit)` 结算，复用现有飘字 `F.FX.text` 与爆点 `F.FX.burst` | 怪物血量/存活在 Combat，技能只发起结算 |
| `player.js` | 技能动作名与时长 | `P.playAction(name, dur)` 驱动 `arms[]` 摆动（现有骨架已支持）；位移技能还需要**直接改 `P.pos`**，必须先 `updateCamera` 再移动 | 位移/前摇状态在技能系统 |
| `rank.js F.Skills` | 战斗等级 | 解锁门槛、等级系数 `level_mult` | 等级数据在 Skills |
| `interact.js` | 触摸/键鼠输入 | 返回"本次能否释放" UI 层 Steven 给它一份 `Inter.skill-blocking` 判定：正在采集/对话/开箱/拆卸模式下禁止释放技能 | — |
| `ui.js` | 装配的技能列表 | HUD 上 3~6 个技能按钮（**触摸端必须有屏幕按钮**，否则移动端没有"右键/Alt"可用），带 CD 遮罩与资源不足灰显 | UI 不持有战斗状态，只读取 |

### 移动端（iOS/Android/平板）专项

- 技能按钮常驻右下热区，直径 ≥44pt，间距 ≥8pt，不与其他 UI 重叠；
- **长按需显示技能说明气泡**（因为触摸没有 hover）；
- 释放方向与 samples：touch 目标选择采用「朝向最近目标 + 前方扇形」而非精确指向（手指点不到精确角度），
  位移/地面类技能需要额外的一次"确认朝向"或直接用当前朝向（草案：**用当前朝向**，减少操作步数）。

## 6. 玩家反馈（看 / 听 / 手感）

- **看**：起手时人物有一个明确可辨的动作（重斩高举→下劈、突进前倾），不是普攻同款的挥砍；路径有实体表现（飞刃 mesh、突进拖尾、地刺警示环），并配合现有 `F.FX` 的飘字；技能面板 CD 遮罩从上往下退。
- **听**：起手一声起势音、`damageT` 一声命中音（暴击时更高更亮）、击中不同材质（毛皮/岩石/水体）有不同音色。
- **手感**：前摇 0.16~0.45s 分级——越强的技能越慢（玩家能感到"这招更重"）；命中有 0.06s 的极短 `hitstop`（时间暂停感），仅 BOSS 与终结技启用，常态关闭以免拖沓。

## 7. 验收口径

- [ ] 八个技能各自能被真实触发（按键 + 触摸按钮两条路径都能）
- [ ] 每个技能的伤害在 `damageT` 这一帧结算，**不多也不少一次**（e2e 用 GMock 计数结算次数）
- [ ] 冷却生效：CD 内重复触发不改变状态、不消耗资源
- [ ] 资源不足时不释放、有提示、不消耗
- [ ] 五种路径各自命中被Case覆盖：扇形只吃前方、圆形吃身后、`dash` 沿途每个目标一次、`projectile` 不穿墙、`ground` 延迟结算
- [ ] 位移技能不会把玩家送出世界边界 / 副本边界 / 卡进建筑
- [ ] 低帧率（人为降帧）下路径不穿透目标
- [ ] e2e 与冒烟全绿，且**截图能看出技能正在释放**（帧证据存 `production/qa/evidence/`）

## 8. 开放问题（这些不到你拍板不动代码）

1. **资源走体力（A）还是新增法力（B）** — B 涉及存档 schema 变更。
2. **技能释放按键**：候选 1/2/3 选哪个？是否接受把现有 `Q`（切种子）挪走？
3. 技能槽数量：**3 个**（够用、面板干净）还是 **6 个**（深度更多、HUD 更挤）？
4. 是否接受「前摇期间可被怪物攻击但不打断」这条偏休闲的规则？要不要给 BOSS 战加打断形成压力？
5. 终结技等高级技能的解锁等级（Lv.45）是否合适？当前全身 Advanced 技能 MAX 60。
