# GDD：画质 / 贴图 / 人物模型 / 骨骼动画

- **ID**：art-upgrade
- **Status**：Draft
- **依赖系统**：`world.js`（地形 / 水体 / 天空 / 草 / 云 / 昼夜）、`creatures.js`（人物 / 动物 / 怪物模型）、`props.js`（零件与 merge）、`main.js`（画质开关初始化）
- **被谁依赖**：全部渲染表现；移动端性能预算
- **优先级层**：Polish
- **MVP**：No

## 1. 目的与玩家价值

**现状（已核实）**：

- 渲染全靠程序化几何 + 顶点色（`creatures.js:3` 明示「无贴图、无骨骼、无外部资源」）；
- 玩家模型（`creatures.js:37 createPlayerModel`）返回 `{group, head, arms[2], legs[2], torso}`，四肢是**带支点的 pivot Group**，动画在 `player.js:226-280` 里直接写 `arms[i].rotation.x`——没有骨架、没有蒙皮，动作是正弦曲线拼出来的；
- 怪物走 `InstancedMesh` 单 mesh（`creatures.js:309`），连部件级的动作都做不到，攻击只能整体倾斜；
- 画质开关已有：`World.setGrassQuality`（0~3）、`setShadows`、`setFloraDensity`（上一轮新增），PC / 移动端已经有分级入口。

这份 GDD 要回答的是：**在不破坏「零外部资源、低多边形、读谊 seconds 就能开玩」这三个项目前提下，画面与动作能往上抬多少。**

非目标：不做 PBR 管线、不做烘焙光照贴图到 AssetBundle（项目没有资源管线）、不追求写实，保持低多边形这块牌子。

## 2. 核心机制

### 2.1 贴图：从「无」到「程序化 CanvasTexture」

保留零外部资源的原则，用 **Canvas 2D 在运行时画纹理**，一次性生成后常驻：

| 纹理 | 用途 | 生成方式 | 分辨率预算 |
| --- | --- | --- | --- |
| `grass_detail` | 地形草地近景细节，与顶点色相乘，杀掉大片同色 | 值噪声 + 三层不同频率，`DataTexture` 更好（省 Canvas 开销），256×256 | 256kB |
| `wood` | 建筑 / 工具的木纹 | 条纹 + 扰动，128×128 | 64kB |
| `stone` | 岩石与石质建筑 | 斑点噪声，128×128 | 64kB |
| `water_norm` | 水面法线扰动（替代现在的纯色波） | 两张正弦叠加成法线贴图，256×256 | 256kB |
| `sky_grad` | 天空渐变替代现在的 shader 计算 | 64×512 | 64kB |

硬约束：

- **总预算 ≤ 1MB 显存**（低端手机友好），生成后 `texture.needsUpdate = true` 一次性上传，之后不再改动；
- 所有纹理必须 `RepeatWrapping` + 2 的幂，才能在 WebGL1/mobile-GL 上安全重复（`three r159` 支持 NPOT 但 reptition 仍建议 POT）；
- **移动端自动降档**：检测到粗指针设备时，`grass_detail` 与 `water_norm` 降到 128×128；
- 必须有 fallback：Canvas 不可用时（极端环境）退化为纯顶点色，不得白屏或黑模型。

### 2.2 画质升级的三条主线

| 主线 | 现状 | 提案 | 成本 / 风险 |
| --- | --- | --- | --- |
| 光照与氛围 | 平行光 + 半球光 + 点光；有昼夜 | ①给傍晚 / 夜晚加一座微妙的冷色补光（現在夜晚偏黑，玩家抱怨过）；②水面加入浅滩泡沫——已有水深贴图（`world.js:194`），可以把这张图复用成岸边泡沫遮罩 | 低 / 低 |
| 后处理 | 无 | 引入「轻量 bloom」选项：只在高画质档开，亮度阈值 0.85，用于技能特效、传送门、灯火；必须能一键关闭且移动端默认关 | 中 / 中（移动 GPU fill rate） |
| 阴影 | `setShadows(bool)` 单点 shadowmap | 保持单张 map，但把 PC 高画质档的分辨率从现状提到 2048，并把 bias 调校一次解决地面 acne | 低 / 低 |

### 2.3 人物模型：分层骨骼（推荐）vs 真骨骼（备选）

这是本项目最大的一块歧义点，先把话说清楚：

**真骨骼（SkinnedMesh + Skeleton）**：要给 `createPlayerModel` 的每一个圆柱/圆球蒙皮绑骨骼，意味着 abandon 现有的 `mergeParts` 单 mesh + pivot 的做法，重做权重、重做异步 empirically 动画系统。**工作量以周计**，而且怪物的 InstancedMesh 管线要跟着改才能共享收益。

**推荐方案：保留程序化层级，做「动画层 + 曲线升级」**——性价比高得多：

1. **动画状态机替代零散的 if**：现在钓鱼时用 `fs.phase` 的 if-else 直接改 rotation（挺 ruins `player.js:255-277`），改成一份动画表 `{state: [{joint, from, to, ease, dur}]}`，由统一的 `Anim.play(state)` 驱动。这样加技能动作只是往表里添一条，不再续 `if` 链。
2. **加入 straightforward secondary motion（次生动）**：给头发/披风/工具挂一个跟随速度的滞后旋转（velocity → target rotation 阻尼），跑动时会有惯性甩动，这是观感升级最便宜的一笔。
3. **呼吸与重心**：站立时躯干做 0.6Hz 的极轻微上下（振幅 0.015m），起跳/落地时有过冲压缩（落地 -0.08m 回弹）——不换模型就能「活」起来。
4. **面部**：眼睛现在是两颗球贴图顶点色。可给眨眼加一个「随机 3~6 秒一次、scale.y 压到 0.1 再回来 100ms」的动画，成本几乎为零、情感反馈很大。

如果将来真的要真骨骼，推荐路径是 **先做 2.3 的动画层**（它是骨骼动画的上位兼容 API），到时把 driver 换成 SkinnedMesh 即可，上层不用改。

### 2.4 怪物动作

怪物是 InstancedMesh 单 mesh，**不能**做部件级动画（`creatures.js:190` 已注明「逐部件骨骼动画要改渲染管线，不做」）。可以做的：

- 攻击时的整体前倾 + 后坐可以利用 instanceMatrix 做每实例的旋转，不改管线；
- 受击时整体缩放弹一下（0.1s）+ 顶点色不变的情况下改 instanceColor 闪白 0.12s——**注意遵守上一轮的约束：这是瞬时反馈而非常驻高亮**；
- boss 出场可以临时多实例化一个 mesh（已是 `sc: 2.0` 单独实例），给它更强的动作，代价可接受。

## 3. 公式与数值（性能预算）

| 指标 | PC 目标 | 移动 / 平板目标 | 降级手段 |
| --- | --- | --- | --- |
| 稳定帧率 | ≥ 60fps @1080p | ≥ 30fps @设备原生分辨率 | `dp`（设备像素比）上限：桌面 1.75、移动 1.25 |
| Draw call | ≤ 220 | ≤ 140 | 草 / 花 / 浆果已是 instanced；剩余压力在建筑与道具的静态批次，必要时按区域合批 |
| 显存 | ≤ 320MB | ≤ 160MB | 纹理预算 1MB；shadowmap 移动端降到 1024 |
| 首屏可交互 | ≤ 4s | ≤ 8s | 纹理生成排在 `requestIdleCallback`，每帧最多生成一张，绝不阻塞开局 |
| triangle count | ≤ 1.2M | ≤ 0.6M | 已有`setGrassQuality` / `setFloraDensity` |

标定方式：在 `main.js` 里挂一个 10 秒滑动窗口的帧时间统计；桌面端渲染耗时超过 12ms、移动端超过 28ms 时自动降一档草地密度。该自动降档是**可选开关，默认关闭**，避免画质自己变化让玩家困惑。

## 4. 边界与异常用例

| 情况 | 行为 |
| --- | --- |
| `document.createElement('canvas')` 取不到 2D context（极端 WebView） | 整条纹理管线跳过，全部退化为顶点色，游戏照常可玩 |
| 纹理生成耗时阻塞主线程 | 分帧生成（每帧一张），首帧用顶点色占位；生 fails 也不阻塞开始游戏 |
| 设备像素比异常（如 4x） | clamp 到上面表格的上限 |
| WebGL 上下文丢失（`webglcontextlost`） | 监听事件并记录当前画质档；恢复时重建纹理，已生成的 canvas 若仍然存活则复用 |
| 低端机开 Bloom 后帧率崩塌 | Bloom 默认仅高画质档；并提供一键「画质恢复默认」，且自动降级（可选）默认关 |
| 内存不足被系统杀 | 移动端 shadowmap 与纹理同时降档；不预生成 sky_grad 这类可计算的东西 |

## 5. 与其他系统的接口

| 对端 | 输入 | 输出 |
| --- | --- | --- |
| `main.js` | 画质设置（草地密度 / 阴影 / 新 Bloom） | 初始化时按设备决定是否降档，**保留现有「高画质默认」的手感** |
| `world.js` | 新建的 `F.Tex` 纹理模块 | 地形 / 水面 / 天空材质换上 map；assign materials 时保持现有 vertexColors 不冲突 |
| `player.js` | `Anim.play(state)` | 现有直接改 rotation 的代码逐步迁移到动画表 |
| `ui.js` 设置面板 | 新增 Bloom 开关 | 与现有草地/阴影/音效开关同款式，不改面板结构 |

## 6. 玩家反馈（看 / 听 / 手感）

- 看：草地有细碎的颜色变化而不是大片同色；水面闪烁的泥浆 foam 让岸边有潮湿度；角色站立时有呼吸、跑步时有披风惯性、偶尔眨眼——**第一眼就能感到它比以前「活」**；
- 听：本份 GDD 不负责音频（见 `audio.md`），但视觉与音频的节奏点要对齐：技能命中的亮度闪的同时也有音效 onset；
- 手感：**画质升级不得以牺牲操作响应为代价**。任何帧率下降都优先通过降纹理分辨率与 Shadowmap 解决，绝不动输入采样率（鼠标 sensitivity 与 input 采样保持现状）。

## 7. 验收口径

- [ ] 五张程序化纹理全部生成成功（`F.Tex.get('grass_detail').image` 存在且尺寸正确）
- [ ] Canvas 不可用的极端路径fallback 验证：临时把 `getContext('2d')` 打桩返回 null，游戏仍可玩、无 JS 报错
- [ ] 桌面 1080p 下 60fps 保持（10 秒采样均值帧时间 ≤ 16.7ms），移动端 chromium 模拟节流下 ≥30fps
- [ ] 显存增量 ≤ 1MB（用统计 ARB/potydenviron 粗略核对 + drawcall 计数不上升）
- [ ] 人物有清晰可辨的新动作：呼吸 / 眨眼 / 落地压缩，截图存证（`production/qa/evidence/`）
- [ ] Bloom 开关生效且默认在移动端关闭
- [ ] 三张原图 / 三张新图 对比截图（客观为上幂等：同一坐标同一时刻同一相机）

## 8. 开放问题

1. 是否接受引入后处理 Bloom（成本最大、收益最强的一观感升级）？还是先只做纹理与动画？
2. 动画层重构（`Anim.play`）改动会触及 `player.js` 现状 if-else，是否在同一个 Story 里做？
3. 「真骨骼 / SkinnedMesh」要不要立项单开一轮？预计工作量以周计。默认建议本轮不做，只把上位 API 铺好。
4. 次生动（披风 / 头发 / 工具惯性）要不要给 NPC 与怪物也上？（玩家 quadruped 优先还是全量？）
5. 自动降画质（动态 dpi）是否启用？默认建议关闭，避免玩家感到画面自己变了。
