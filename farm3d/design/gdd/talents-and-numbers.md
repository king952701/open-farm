# GDD：天赋树与数值体系

- **ID**：talents-and-numbers
- **Status**：Draft
- **依赖系统**：`rank.js`（`F.Skills` 八项技能等级 + `need(lv)` 曲线）、`combat.js`（伤害结算）、`util.js`（存档读写）
- **被谁依赖**：战斗技能（`combat-skills.md`）、UI 技能面板、排行榜数值展示
- **优先级层**：Core
- **MVP**：Yes

## 1. 目的与玩家价值

**现状**：`rank.js:31` 的 `F.Skills` 是八条纯等级曲线（农耕 / 采集 / 挖矿 / 钓鱼 / 畜牧 / 烹饪 / 炼金 / 战斗，MAX 60，升级所需经验 `need(lv) = 60 + 40·lv^1.35`）。这些等级目前只在门槛判定和排行榜上有用——**升满一级不产生任何玩家能感知的数值变化**，挖了两百次矿换来的 LV 增长缺少反馈。

本系统把「等级」翻译成「选择」：每升级一次得 1 点天赋点，投入八棵天赋树；每棵树 3 层（T1/T2/T3），每层 2 选 1。目标有两个：让同等级的挖矿流和战斗流在面板上有本质差别；给战斗技能的倍率、暴击、冷却一个成长来源。

非目标：不做洗点付费、不做装备重锻一类数值膨胀系统、不动八项技能本身的经验曲线（那是另一条平衡线，本轮不碰）。

## 2. 核心机制

### 2.1 天赋点产出

| 来源 | 点数 | 说明 |
| --- | --- | --- |
| 八条技能线各自升级一次 | +1 | **按升级次数给，不是按等级**：农耕从 3 升到 4 给 1 点，战斗从 3 升到 4 也给 1 点 |
| 理论上限 | 8 × (60 − 1) = 472 点 | 八条线全满才拿得到，正常玩家远达不到；节点总需求见 §8 开放问题 4 |

### 2.2 树结构

每棵技能树 = 3 层，层 1 是二选一，层 2 三个节点，层 3 二选一，合计 **6 个节点**；每个节点可投 0~3 级（rank）：

```
        T1-a        T1-b            ← 层1：二选一（互斥）
      /       \   /       \
    T2-a     T2-b     T2-c          ← 层2：需<｜hy_place▁holder▁no▁813｜>本树至少一个 T1 节点 ≥1 级
      \        |        /
        T3-a        T3-b            ← 层3：需至少一个 T2 节点 ≥2 级
```

规则：

- **解锁的等级门槛随层递增**：T1 需该项技能 Lv.5 / 15 / 30（对应 rank 1/2/3）；T2 需 Lv.20 / 35 / 45；T3 需 Lv.40 / 50 / 55。
- **互斥只发生在同层内部**：T1-a 与 T1-b 二选一；T3-a 与 T3-b 二选一；T2 三个节点互不排斥。
- **前置要求**：投资任意 T2 需本树至少一个 T1 节点 rank ≥1；任意 T3 需至少一个 T2 节点 rank ≥2。
- **洗点**：系统面板提供洗点（草案：免费。休闲养成里用洗点惩罚玩家不合适；若要有代价见 §8 开放问题 3）。

### 2.3 八棵树草案

**战斗树（combat）** —— 与 `combat-skills.md` 直接联动：

| Tier | 节点 | 每级效果 | 满级 3 级合计 |
| --- | --- | --- | --- |
| T1-a | 磨砺 | 普攻伤害 +6% | +18% |
| T1-b | 锐锋 | 暴击率 +3%（加法） | +9% |
| T2-a | 技能大师 | 所有技能伤害 +8% | +24% |
| T2-b | 疾风 | 技能冷却 −5% | −15% |
| T2-c | 体能回收 | 每次击中回复体力 +0.5 | +1.5 |
| T3-a | 处决者 | 对生命低于 40% 的目标伤害 +10% | +30% |
| T3-b | 暴烈 | 暴击伤害 +0.25（基础 1.8 → 2.05 / 2.30 / 2.55） | 暴伤 ×2.55 |

**其余七棵**按统一口径在落地 Story 里逐棵补齐：

- 采集类（挖矿 / 采集 / 钓鱼 / 畜牧）：一支给**效率**（消耗次数减少、动作更快、多选 specialists 概率），另一支给**产出**（额外掉落、更高品质、稀有物品概率）。
- 生产类（农耕 / 烹饪 / 炼金）：一支给**产量**，另一支给**品质与时效**（产物等级 +1、buff 时长延长、烹饪副产物）。

写面板文案时的硬要求：**每个节点都必须写成玩家读得懂的句子**（例如「矿石额外获得 +12%」），不许把 `mult: 1.12` 直接显示出来。

## 3. 公式与数值

### 3.1 统一伤害公式（普攻与技能共用一套）

```
base       = tool_dmg[tool] + equip.atk
atk_scale  = 1 + combat_lv * LV_COEF + Σ talent_atk_pct
skill_dmg  = base * atk_scale * skill_mult * (1 + Σ talent_skill_pct)
crit_rate  = clamp(0.12 + Σ talent_crit_pct, 0, 0.75)
crit_mult  = crit ? (1.8 + Σ talent_crit_dmg) : 1.0
level_mult = 1 + clamp((combat_lv - mob.lv) * 0.01, -0.20, +0.30)
damage     = max(1, round(skill_dmg * crit_mult * level_mult * buff_mult))
```

| 常数 | 值 | 来源 / 说明 |
| --- | --- | --- |
| `tool_dmg` | axe 14 / sword 22 / pick 12 / hammer 10 / sickle 8 / hoe 6 / rod 3 / can 2 / feed 2 / seed 2 / none 4 | 沿用 `combat.js:307`，本轮不改，避免破坏既有手感 |
| `equip.atk` | `F.EQUIP[id].atk` | 沿用 `combat.js:308` |
| `LV_COEF` | 0.02 / 级 | 满级 +120%；**偏强，待平衡确认**，见 §8 |
| `target_def` | 0（本轮不引入） | `combat.js:22 MOBS` 只有 hp/atk/spd，没有防御字段。公式预留位置，将来引入需整表重算 |
| `buff_mult` | `P.strT > 0 ? 1.5 : 1` | 沿用力量药剂（`combat.js:309`） |
| 暴击率上限 | 0.75 | 防止必爆导致随机性消失 |
| 最低伤害 | 1 | 沿用现状，避免 0 伤害出现「打不死」假象 |

### 3.2 `level_mult` 为什么是双向夹紧

低等级打高级怪最多被压制 −20%——明显吃亏但仍有翻盘空间；高等级打低级怪最多增益 +30%——有爽感，但不会把新手村史莱姆一击蒸发到失去尺度。两端都用 `clamp` 夹紧，避免跨三十级的极端值把公式拉爆。

### 3.3 数值 golden case（公式验收用）

| 案例 | 输入 | 期望结果 |
| --- | --- | --- |
| 新手：战斗 1 级、徒手、无装备、目标史莱姆 Lv.2 | `base=4, lv=1, mob.lv=2` | `atk_scale=1.02, level=0.99 → 4.04 → 4` |
| 中期：战斗 20 级、铁剑（22+15）、T2-a rank2、目标强盗 Lv.20 | `base=37, atk_scale=1.40+0.16=1.56` | `57.7 → 58`（不暴击） |
| 同上且暴击 | `×1.8` | `104` |
| 终结技（×2.6）暴击 + T3-b rank3（×2.55） | `58 × 2.6 × 2.55` | `384`（同一 base，对比 baseline 58 → 倍差约 6.6×） |

## 4. 边界与异常用例

| 情况 | 行为 |
| --- | --- |
| 点数不足时点击节点 | 节点灰态，点击播 `bad` 提示音，不扣点 |
| 前置未达成 / 同层互斥 | 节点灰态并在 tooltip 写明原因（如「需先投资 锐锋 1 级」） |
| 中间量出现 `NaN` / `Infinity` / ≤0 | 统一走 `Number.isFinite(x) ? x : fallback`，保证任何情况下都输出有限数 |
| 伤害数值溢出（巨额倍率叠加） | 单点硬顶 99999，排行榜与飘字同样夹紧，不许撑破 UI |
| 旧档没有 talents 字段 | 补 `{}`，并按当前八项等级重算出应得点数发还玩家。**不清零等级**，老玩家更新后不吃亏 |
| 存档里出现已删除的节点 id | 忽略该节点、把投点退回可用点，并 `console.warn` 一次便于排查 |
| 连点快速投资 | UI 层 120ms 节流，防止手滑一次点掉 5 点 |
| 洗点 | 返还全部点数、清空树、`Audio2.ok()` + toast；操作前给二次确认并显示返还数量 |

## 5. 与其他系统的接口

| 对端 | 输入 | 输出 |
| --- | --- | --- |
| `combat-skills.md` | 各节点的加/乘贡献 | 提供 `Talents.mods()`，返回一个聚合对象 `{atk_pct, skill_pct, crit_pct, crit_dmg, cdr, lifeOnHit}`。战斗侧**只消费聚合值**，不在热路径里逐节点遍历 |
| `rank.js F.Skills` | 八项等级 | 决定节点解锁门槛与可用点数 |
| `ui.js panelSkill` | 玩家的查看 / 投资 / 洗点操作 | 现有技能面板加一个「天赋」子页（复用现有 Tab 外壳） |
| 存档 | `Game.save / load` | **schema 变更**：新增 `G.talents`（投资结构）与 `G.talentPts`（剩余点数） |

> ⚠️ 存档 schema 变更属于 automation=guided 下的必问类目，见 §8。

## 6. 玩家反馈（看 / 听 / 手感）

- 节点三种视觉态：可投（轻微描边亮度）/ 已满（实心 + 等级点）/ 不可投（灰态）；
- 投资成功瞬间节点做 0.9→1.0 的弹性缩放（120ms），并弹 toast「已投资：锐锋 2 级」；
- 洗点前二次确认并明确写出返还数量，避免误操作把树洗空；
- **每个节点都能看到它带来的具体收益**（tooltip 写「矿石额外获得 +12%」而不是 `yield_mult`）；
- 面板打开时的默认焦点项带键盘可达性（`role="treeitem"`、`aria-expanded`），与已有 Tab + 键盘操作习惯一致。

## 7. 验收口径

- [ ] 八棵树可在面板浏览、投资、洗点，且三态视觉正确
- [ ] 点数守恒：剩余点 + 已投点 = 理论产出（e2e 断言）
- [ ] 前置与互斥规则生效，不满足时不能投资并给出原因
- [ ] 旧档载入后等级完整保留，天赋自动补默认值且点数发还正确
- [ ] §3.3 四个 golden case 在自动化里跑出精确数值（含取整规则）
- [ ] 天赋真的进入战斗：投满 T2-a 后同一技能伤害按公式提升，前后对比截图存证

## 8. 开放问题（不拍板不动代码）

1. **`LV_COEF` 取 0.02 还是 0.015**？满级 +120% 再叠加天赋 T2-a(+24%) 与暴伤，后期可能数值失控。倾向先取 0.02，靠一次试玩报告校正。
2. **是否给怪物引入 `def` 防御字段**？公式已预留，但要给 8 种怪物补表并整表重算。建议本轮不引入，保持「怪物只靠血量与攻击说话」的简约感。
3. **洗点是否要有代价**？免费 / 金币（如 500 × 已投点数）/ 特殊道具三选一。
4. **点数总量是否收紧**？当前 6 节点 × 3 rank × 8 树 = 144 点需求，而理论产出 472 点，玩家能点满约三成。若改成「每个节点只能投 1 级」，需求降到 48 点，更接近「专心练两个专精」的预期——倾向后者。
5. 七棵非战斗树的具体节点数值，是否等战斗树验收通过后再动手（建议：是，避免同时铺开导致平衡没法收敛）。
