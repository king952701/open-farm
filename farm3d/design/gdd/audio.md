# GDD：音乐与音效

- **ID**：audio
- **Status**：Draft
- **依赖系统**：`util.js`（`F.Audio2` 现成的 WebAudio 合成器）、`world.js`（昼夜 `World.time`）、`combat.js`（战斗状态）
- **被谁依赖**：全部交互反馈；移动端自动播放策略
- **优先级层**：Polish
- **MVP**：No

## 1. 目的与玩家价值

**现状**：`F.Audio2` 是纯程序化合成（为保障 blip / ok / bad 等短音效），**完全没有背景音乐**。八小时游玩下来只有零星的提示音，没有一个能把「早晨的农场 / 傍晚的湖畔 / 副本里的紧张」串起来的声音层；这在休闲养成里直接决定了「待得下去」还是「玩十分钟就关」。

目标：零音频文件（保持项目「无外部资源」的原则），用 WebAudio **实时合成**出一套可长期待着也不腻的音乐系统 + 成体系的音效字典，并且不喧宾夺主——玩家意识不到音乐存在，但关掉会立刻觉得空。

非目标：不做外部音频文件 / CDN 拉取（会破坏离线可玩与首屏预算）、不做专业级的音乐编曲追求，放在「环境音乐 + 响应式 cue」这个尺度上。

## 2. 核心机制

### 2.1 音乐：一层层叠起来的响应式环境音乐

不是「循环播放一首曲子」，而是**四个可持续层**按场景淡入淡出：

| 层 | 内容 | 音量权重随什么变化 |
| --- | --- | --- |
| `pad` | 缓慢的和弦垫音（三角波 + 低通），根音随昼夜变化 | 始终存在（基础空气感） |
| `arp` | 五声音阶的琶音，每 2 小节换一次音型 | 时间：白天活跃度高，深夜几乎静音 |
| `pulse` | 极轻的低频心跳音 | 场景：进入战斗 / 副本时淡入，离战 8 秒后淡出 |
| `texture` | 环境点缀（清晨鸟鸣、夏夜虫鸣、近岸水声） | 位置：靠近水源 / 森林时权重上升 |

调式安排（保持「田园」感，避免大小调的强情绪）：

- 清晨 5–9：D 大调五声 + 高八度琶音，明亮轻快；
- 白天 9–17：G 大调五声，中等密度；
- 黄昏 17–20：A 小调五声（加 4 音后缀），带一点收工感；
- 夜晚 20–5：降 E 大调五声、密度降至 30%、pad 更厚更暗。

**过渡必须是 4~8 秒的交叉淡变**，绝不能突然切歌。

### 2.2 战斗 cue

进入战斗（存在目标且距离玩家 10m 内）后 6 秒内：

- `pulse` 层淡入，`arp` 换一套更短促的音型；
- **BGM 总音量 duck 到 60%**，让技能音效有空间（动态混音）；
- BOSS 战：加一条低音黑名单 ostinato（重复短句），每 2 小节重复，制造压力。

### 2.3 音效字典（替代现在的散落调用）

现在各处直接调 `Audio2.blip(freq, dur, type, gain)`，参数散在代码里。统一成**语义字典**，调用方只写动作名，音色可以后期统一调整：

| 类别 | ID 提案 | 现状调用 | 说明 |
| --- | --- | --- | --- |
| UI | `click / hover / open / close / error` | 部分有 `Audio2.ok / bad` | 统一入口，禁止在 UI 层再写裸频率 |
| 采集 | `chop_wood / mine_stone / dig / harvest / water / fish_cast / fish_bite` | `blip(180,...)` 硬编码 | 按材质区分音色（木 vs 石），材质映射到 `[180, 260]` 的低频方波 / 三角波 |
| 战斗 | `swing / hit_soft / hit_hard / crit / levelup / death` | `combat.js:305` 硬编码 180Hz | 暴击与终结技要有明显不同的音色权重，让「打出暴击」有听觉奖励 |
| 技能 | `cast_start / cast_hit / dash / ground_slam / heal` | 无 | 与 `combat-skills.md` 对齐：起手音 → `damageT` 命中音，两者音高差三度以上 |
| 环境 | `bird / cricket / water_lap / wind_gust` | 无 | 随时间与位置触发，带 8 秒以上的随机间隔，避免规律感 |
| 系统 | `skill_up / quest_done / trade / door` | 部分 | 与现有 toast 同拍发出 |

硬约束：**同一 ID 200ms 内只允许发声一次**（连点时防止音效堆叠成噪音）；移动端 Safari 必须在**首次用户手势**后才 resume AudioContext（现有代码是否已经处理需要在实现时核实，未处理就先补）。

## 3. 公式与数值

```
music_layer_gain(layer) = base[layer] * timeCurve[layer](t) * sceneWeight[layer](scene)
```

| 常数 | 值 | 说明 |
| --- | --- | --- |
| `base.pad / arp / pulse / texture` | 0.22 / 0.16 / 0.10 / 0.14 | 各层的基准音量（线性 gain） |
| 主输出上限 | 0.55 | 避免盖过音效；系统设置里的「音乐音量」乘在这一层之后 |
| 交叉淡变时长 | 6s（昼夜） / 2s（战斗切换） | 线性 ramp，禁止突变 |
| 节拍 | 72 BPM（白天） / 60 BPM（夜晚） | 慢速，休闲基调 |
| 环境音触发间隔 | `[8, 22]` 秒随机 | 每次随机取一个 environmental ID |
| duck | 战斗时音乐 ×0.6，退出战斗 1.5s 内恢复 | 战斗状态退出后有 6 秒冷却，防止反复进出导致音量抖动 |
| 音效并发上限 | 同时 8 个 | 超出的低优先级（UI hover）直接丢弃 |

## 4. 边界与异常用例

| 情况 | 行为 |
| --- | --- |
| 浏览器禁止自动播放（iOS Safari） | 首次点击/按键时 resume AudioContext；在此之前**静默不报错** |
| `AudioContext` 创建失败 | 整个音频模块降级为空实现（所有调用为 no-op），游戏照常运行 |
| 玩家关闭音效开关（`G.opt.audio`） | 立即停全部 source；音乐下次开关打开时从当前场景层重建 |
| 切到后台（标签页不可见） | `visibilitychange` 时暂停音乐，回到前台时恢复（避免回来时听到一段已经跑飞了很久的循环） |
| 长时间运行后的 oscillator 泄漏 | 每个音色用完必须 `stop()` 并 `disconnect()`；增加一个上限断言：活跃 source > 64 时强制回收最老的 |
| 同一音效瞬间重复触发 | 200ms 内同 ID 只响一次 |
| 低性能设备 | 环境层与 `texture` 层在粗指针设备上自动降采样（每 2 个音型跳过一个） |

## 5. 与其他系统的接口

| 对端 | 输入 | 输出 |
| --- | --- | --- |
| `world.js` | `World.time`（昼夜）、玩家坐标（水面/森林距离） | 决定各层权重与调式 |
| `combat.js` | 是否进入战斗、目标是否为 BOSS | 触发 duck 与 ostinato |
| `combat-skills.md` | `cast_start` / `cast_hit` 时机 | 技能的两个音效锚点必须在 `damageT` 同一帧发出 |
| `ui.js` | 音量与开关设置 | 设置面板沿用现有开关；新增「音乐音量」与「音效音量」两条（现有一条 `音效`） |

## 6. 玩家反馈（听 / 看 / 手感）

- 听：白天在村里有轻快的琶音垫底；走到湖边水声变明显；夜里换成稀疏低沉的音符加虫鸣；下副本时心跳低频浮起；
- 看：可选一个很小的「♪ 正在播放：晨间田园」HUD 提示（切换曲式时一闪而过 2 秒），让玩家明白音乐是响应式的；
- 手感：**音频 onset 必须与画面帧对齐**。技能命中音要在 `damageT` 同帧触发，晚一帧（16ms 以上）玩家就会觉得「打击感软」；这是最容易被人忽略、但影响最大的一条。

## 7. 验收口径

- [ ] 四个音层能独立开关，且淡变不发生爆音（用 OfflineAudioContext 渲染一小段并检测峰值 ≤ 0.99）
- [ ] 昼夜四个时段各播放 20 秒，录到的峰值与平均声压在 ±3dB 内（不会某段突然很吵）
- [ ] 战斗进出 duck 生效，且 6 秒内反复进出不会造成音量抖动
- [ ] 全部字典 ID 都有对应音色；e2e 逐个调用不报错
- [ ] iOS Safari 自动播放限制：首次手势前无报错、手势后能发声（需真机或 UA 模拟 + 备注说明无法完全验证）
- [ ] 连续跑 5 分钟，活跃 AudioNode 数量不增长（泄漏检查）
- [ ] 技能 `cast_start` 与 `cast_hit` 在 `damageT` 同帧触发（用时间戳断言差值 < 20ms）

## 8. 开放问题

1. **要不要让玩家自己选择"曲式风格"**（如田园 / 悠远 / 节庆三套和声走向）？还是一套贯穿全场？
2. 是否接受「HUD 上短暂显示曲式名」这种可视提示？（可能破坏现有的极简 HUD）
3. 音效音量与音乐音量是否分成两条设置（现状只有一条 `音效` 开关）？——建议分，但需要改设置面板。
4. 环境鸟鸣/虫鸣是程序化合成（保持零资源）还是接受极小体积的采样文件？**倾向程序化**，代价是音色没那么真。
5. 帧对齐预算：允许的音频延迟上限（建议 20ms；超过就宁可牺牲音色复杂度来保对齐）。
